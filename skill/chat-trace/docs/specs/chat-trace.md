# Chat Trace 功能规格

## 文档状态

- 状态：Ready to implement。
- 目标：用于保存当前 session 历史问答的 Skill。
- 来源：当前 session 中用户的初始要求及后续简化、编号和步骤调整。
- 已检查：`skill/chat-trace/` 已存在；相邻 Skill 使用独立目录组织。当前目录尚无实现。
- 本文只整理功能要求，不创建 Skill 实现，也不执行问答归档。

## 目标与范围

完整保存用户选中的问题，简洁总结对应 AI 回答，通过两次确认后保存为中文和英文 Markdown 文件。

仅实现下述四步流程。不要恢复已删除的历史检索流程、第五步、独立保存核验流程或其他扩展功能。

## 第一步：整理范围

整理范围为当前 session 的所有对话，AI 回答使用当前能读取的内容。（BR1、BR6）

不增加其他 session 检索、时间范围选择或历史来源选择流程。

## 第二步：展示问题选择表

按对话顺序编号，使用数字 1、2、3……。（BR2、BR3、BR6）

| 编号 | 用户问题原文（完整） | 是否保存 |
|------|----------------------|----------|
| 1 | 用户问题原文 | 待选择 |
| 2 | 用户问题原文 | 待选择 |

此阶段不填写 AI 回答摘要。

用户可以按编号选择、全部保存或取消。等待用户确认选择后，再进入下一步。

## 第三步：生成已选问答表

只保留用户选中的问题，分别展示中文和英文版本。（BR2、BR3、BR4）

| 编号 | 用户问题原文（完整） | AI 回答简洁总结 |
|------|----------------------|-----------------|
| 1 | 用户选中的问题原文 | 对应 AI 回答摘要 |

摘要要求沿用简化后的草稿：

- 忠实概括实际回答，不新增结论或建议。
- 优先保留结论、关键原因和必要操作。
- 通常使用 1～3 句，必要时使用简短要点。
- 没有可读取的对应回答时，标注“无可读取的 AI 回答”；英文版本使用对应英文表述。

两个版本都完整保留用户问题原文；AI 摘要分别使用中文和英文。英文文件不以翻译后的问题替代用户原文。

默认保存到项目根目录的 `PROJECT_TRACE.zh-cn.md` 和 `PROJECT_TRACE.en.md`，文件不存在时新建，已存在时追加，不覆盖已有内容。（BR4、BR5）

预览中说明默认保存路径和新建或追加方式，供下一步确认。

## 第四步：等待最终确认

只有用户明确确认最终内容和保存方案后才允许写入。

用户要求修改时，更新预览并再次等待确认。

用户取消时，不写入任何归档内容。

## 实现边界

- 两次确认是交互边界，不得在一次连续执行中自行跳过。
- 最终确认后的保存属于第四步，不增加“第五步”标题。
- Markdown 表格的展示转义不得造成问题内容删减或改写；复杂原文的具体排版方式由实现者选择，但必须满足原文完整保留。
- 当前规格文件不是 `PROJECT_TRACE` 归档文件；本次保存规格不等同于用户确认问答归档。
- 规格不要求新增脚本、跨 session 检索、自动去重或额外的独立核验流程。
