# WorkStation rules

## Microchip MCU Development (MPLAB X)

### MPLAB X Project Detection
Treat the current working environment as an MPLAB X project (MPLAB X IDE or the
MPLAB X VS Code extension) when either of these is true:
- The current working directory name ends with `.X` (e.g. `MyProject.X/`)
- The current working directory contains a subdirectory whose name ends with `.X`
  (e.g. `MyProject.X/` inside a workspace root)

### Protected Directory: mcc_generated_files
Inside an MPLAB X project (see detection rule above), the `mcc_generated_files`
directory located directly under the `.X` project folder is generated by MPLAB
Code Configurator (MCC) and is considered **read-only by default**.

Rules:
- Do NOT edit, create, delete, or overwrite any file under
  `<ProjectName>.X/mcc_generated_files/` without explicit per-request confirmation.
- Before making ANY change to a file in this directory, you MUST ask the user
  for confirmation using the question/ask tool (or by explicitly asking in text
  if no such tool is available) — every single time, even if a similar edit was
  already approved earlier in the same session.
- In the confirmation prompt, clearly state that the file is MCC-generated and
  that manual edits are typically overwritten when the user regenerates code
  from MCC, so changes may be lost.
- Only proceed with the edit after the user explicitly agrees for that specific
  request. A prior approval does not carry over to later, separate edit requests.
- This restriction applies regardless of how deeply nested the file is under
  `mcc_generated_files/` (i.e. it covers the whole subtree), but the trigger for
  "is this an MCC directory" is only the top-level `mcc_generated_files` folder
  found directly under the `.X` project root.
